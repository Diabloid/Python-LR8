# Python-LR8: Лабораторна робота 8. Unit-тести

## Мета роботи
Ознайомитися з принципами модульного тестування (unit testing) у Python, навчитися створювати, запускати та аналізувати тести за допомогою бібліотеки unittest та фреймворку pytest, а також перевіряти правильність роботи функцій і класів програми.

## Структура проекту

- \math_utils.py\ — модуль базового рівня (функції \dd\, \is_even\, \actorial\).
- \	est_math_utils_unittest.py\ — тести для модуля \math_utils\ з використанням стандартної бібліотеки \unittest\.
- \	est_math_utils.py\ — тести для модуля \math_utils\ з використанням фреймворку \pytest\.
- \ank_account.py\ — модуль середнього рівня (клас \BankAccount\ з методами поповнення, зняття та перевірки балансу).
- \	est_bank_account.py\ — тести для класу \BankAccount\ з використанням \setUp()\ та \	earDown()\.
- \data_manager.py\ — модуль високого рівня (робота з JSON: читання, збереження, фільтрація користувачів за віком).
- \	est_data_manager.py\ — тести з використанням \unittest.mock\ (\mock_open\, \patch\), перевірки викликів функцій та параметризації (\@pytest.mark.parametrize\).

## Виконані рівні складності

### А. Базовий рівень
- Реалізовано функції \dd\, \is_even\, \actorial\ з обробкою граничних значень та типів.
- Написано понад 3 тести для кожної функції в \unittest\ та \pytest\.
- Здійснено порівняльний аналіз \unittest\ і \pytest\.

### Б. Середній рівень
- Створено клас \BankAccount\ із захистом від від'ємного початкового балансу, від'ємних сум поповнення/зняття та перевищення ліміту коштів.
- Написано unit-тести для перевірки початкового балансу, позитивних операцій та винятків (\ValueError\, \TypeError\).
- Застосовано \setUp()\ та \	earDown()\ для ізоляції тестових випадків.

### В. Високий рівень
- Створено модуль \data_manager\ для обробки даних користувачів у форматі JSON.
- Застосовано мокінг (\mock_open\, \patch\) для ізоляції файлових операцій читання/запису.
- Використано параметризовані тести (\@pytest.mark.parametrize\) для перевірки різних вікових меж та некоректних аргументів.
- Проведено аналіз покриття коду тестами (Test Coverage $\ge$ 80%).

## Запуск тестів

### Запуск за допомогою pytest
\\\ash
# Запуск усіх тестів
pytest -v

# Запуск тестів з розрахунком покриття коду (coverage)
pytest --cov=. --cov-report=term-missing --cov-report=html
\\\

### Запуск за допомогою unittest
\\\ash
python -m unittest discover -v
\\\

## Порівняння unittest та pytest

| Критерій | unittest | pytest |
| :--- | :--- | :--- |
| Походження | Вбудований у стандартну бібліотеку Python | Зовнішній пакет (\pip install pytest\) |
| Стиль написання | ООП, наслідування від \unittest.TestCase\ | Функціональний підхід, чисті функції |
| Синтаксис перевірок | Методи \ssertEqual\, \ssertTrue\, \ssertRaises\ | Стандартний оператор \ssert\ |
| Фікстури | Методи \setUp()\ та \	earDown()\ | Гнучка система фікстур (\@pytest.fixture\) |
| Параметризація | Цикли / \subTest\ | Декоратор \@pytest.mark.parametrize\ |
| Звіт про помилки | Базовий traceback | Детальний показ значень змінних при падінні |
